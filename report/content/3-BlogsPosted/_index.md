While learning about containers on AWS, I published three posts in the [AWS Study Group](https://www.facebook.com/groups/awsstudygroupfcj). They are ordered from the motivation for container orchestration, through the choice of orchestration platform, to the runtime components inside Amazon ECS.

### [Blog 1 – Docker already runs on EC2, so why does Amazon ECS exist?](3.1-Blog1/)

This post separates Docker's container-packaging role from Amazon ECS responsibilities for deployment, desired state, recovery, and scaling.

### [Blog 2 – What is the difference between Amazon ECS and Amazon EKS?](3.2-Blog2/)

This post compares AWS-native container orchestration with AWS-managed Kubernetes and explains when each option may fit.

### [Blog 3 – What is the difference between a Task and a Service in Amazon ECS?](3.3-Blog3/)

This post explains that a Task is one running instance of a Task Definition, while a Service maintains the desired number of Tasks for a long-running application.
